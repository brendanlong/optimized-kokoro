# Intentional differences from the reference

The Rust port matches the deployed Python pipeline (`reference/`) except for the differences listed here. Each one says what changed, why, how many reference records it changes, and how it was checked (see "Matching the reference vs simplifying it" in `plan.md`).

| Area | Reference behaviour | Ours | Why | Records changed | Checked by |
|---|---|---|---|---|---|
| SSML (removed feature) | A speech request with `ssml: true` (and `allow_voice_tags`) has its `<speak>` document translated to inline tags (`ssml.py`) | Not supported: the new API has no `ssml` option, and a request that sets it is rejected | Brendan's decision (2026-11-02): Lion Reader doesn't use SSML, and the inline tags we keep (`[pause:Xs]`, `[word](/phonemes/)`; `[voice:...]` was removed later, see below) cover most of the same ground. It also removes an XML parser from the untrusted-input path | 0 in corpus (SSML is a request option, not text) | n/a |
| Text: sentence splitting | A `[word](/phonemes/)` placeholder in the text (`xN`) whose index has more than 4,300 digits makes `int()` raise `ValueError`, failing the request | Treated as text that isn't a placeholder | The request shouldn't fail on hostile input | 0 in corpus | `crates/text` unit tests |
| misaki English | `TypeError` when a punctuation-tagged token starts with `İ` | Returns phonemes | The request shouldn't fail | 0 in corpus (30 of 4,000 random strings) | PR #5 fuzzing |
| misaki English | British `[3ing](-1)` raises `AttributeError` and `[3ing](0.5)` raises `TypeError`: the number reading gets a stress feature, but `_ing` returned `None` | Returns phonemes (the `-ing` form is read in pieces) | The request shouldn't fail | 0 in corpus | PR #5 review (Sol), link fuzzing |
| misaki English | In a run of subtokens without whitespace, tries every span as one word (cubic in the run's length: 1.9 KB of `qx-qx-…` took 8.4 s) | Tries spans of at most 16 subtokens. No lexicon key has more than 13 subtokens, so only dotted abbreviations longer than 8 letters, and numbers whose repeated separators split them into more than 16 subtokens, read differently. `a.b.c.d.e.f.g.h.i` keeps its letter names but gets different stress. | Linear time on adversarial input | 0 of 50,328 recorded calls (corpus, direct misaki cases, fuzz) | `crates/g2p-en/tests/parity.rs`, `tests/scaling.rs` |
| Pipeline: Japanese runs, and Han without a reading (Japanese temporary) | In English text, Han/kana runs with kana are read by misaki's Japanese G2P (`JAG2P`), as they are in Chinese text (`lang` z); Han characters pypinyin can't read go to the English G2P, which often reads them as nothing (`𠮷` in `𠮷野家`, Kangxi radicals like `⼀`) and elsewhere spells them out through espeak (`兙` as "Chinese letter") | Each kana run is read as the English words "Japanese text", and each run of Han characters pypinyin has no reading for as "Chinese text": their phonemes are the English G2P's for those words on their own, read once per pipeline and reused. Han characters with a reading are read by the Chinese G2P, exactly as the reference reads them (`crates/g2p-zh`). Runs of one language with only spaces, apostrophes, hyphens, combining marks or invisible format characters (zero-width space and joiners, direction marks, soft hyphen, word joiner) between them make one placeholder (`カナ カナ` and `兙\u200b兙` are one each), and a placeholder is kept apart by a space from a word right against it on either side, unless there's whitespace already. The rest of the sentence is read as before, and a sentence that is only such a run says "Japanese text". The placeholder is one word for timestamps, holding the run's text. In the Chinese pipeline a kana run is the English "Japanese text" too, in the Chinese voice. `Chunk::unread` counts the runs, and the server logs one count per request, without the text. `Pipeline::with_foreign_g2p` plugs a Japanese G2P in | Brendan's decision (2026-11-03), until the ja G2P is ported: guessing would speak wrong sounds, dropping the run silently loses that something was there, and failing the sentence loses the English around it. For Han characters with no reading, "Chinese text" in both cases, silent or spelled out, follows the same placeholder decision: nothing is dropped silently, and every run without a reading sounds the same | Japanese: 2 of 8,700 English corpus records and 37 of 686 Chinese Wikipedia records; unreadable Han: 0 of 8,700 English corpus records (3 of 74 English records in the committed `zh_mixed` fixture, which puts `兙` in on purpose) | `crates/pipeline/tests/parity.rs` (English records with Japanese runs match the reference with each run's tokens replaced by the placeholder's; Chinese records with Japanese runs match exactly when read with the reference's own Japanese phonemes), `tests/pipeline.rs`; `crates/server` `unread_runs_are_logged_once_without_their_text`, `speaks_english_with_the_real_pipeline` |
| Pipeline: other scripts | `foreign.py` splits out runs of six scripts besides Han and kana (Arabic → `ar`, Cyrillic → `ru`, Devanagari → `hi`, Greek → `el`, Hangul → `ko`, Hebrew → `he`) for espeak; letters of any other script go to misaki's English G2P, which spells them out (`สวัสดี` as "Thai letter twenty-two…"), hands them to its espeak fallback, or reads them as nothing (Javanese, Cham, Meetei Mayek and the other scripts in U+A700–U+D7FF) | Every non-Latin script with a letter or digit in the run makes runs, by the same rules (words joined by spaces, apostrophes and hyphens; Greek needs three letters), and, for the new scripts, with combining marks and invisible format characters (`\p{Cf}`: zero-width space and joiners, soft hyphen) inside them. The six keep `foreign.py`'s voices and rules exactly. Any other script goes to the language espeak-ng's alphabet table (`AlphabetFromChar` in `tr_languages.c`) switches to for an alphabet whose letters are mostly of that script: Armenian → `hy`, Bengali → `bn`, Gurmukhi → `pa`, Gujarati → `gu`, Tamil → `ta`, Telugu → `te`, Kannada → `kn`, Malayalam → `ml`, Sinhala → `si`, Georgian → `ka`, Shavian → the pipeline's English. The script decides, not the first letter, and only letters that lowercase into that voice's alphabet go to it, as espeak lowercases a word before reading it: Georgian capitals (Mtavruli) are read as Georgian, while Nuskhuri, Armenian ligatures (`ﬓ`) or the Tamil Supplement are "Georgian text", "Armenian text" and "Tamil text". A script espeak's table gives no language of its own (Thai, Lao, Tibetan, Myanmar, Ethiopic, Khmer, Mongolian, Coptic in the Greek block, Javanese and the rest of U+A700–U+D7FF that espeak gives Korean, …) is read as "<script> text" with Unicode's name for it, as Chinese and Japanese are above, and so is a run of a new script that espeak reads as nothing. Ethiopic numerals (`፩፪፫`), which misaki read as a number, are "Ethiopic text" too | Brendan's decision (2026-11-03): reading letter names or code points aloud is noise, and espeak already knows which voice reads which alphabet | 3 of 8,700 English records (Bengali, Khmer and Canadian Aboriginal syllabics) and 5 of 1,816 reference requests; not compared | `crates/pipeline/src/foreign.rs` tests, `tests/pipeline.rs` |
| Pipeline: other scripts in Chinese text | In the Chinese pipeline (`lang` z), runs of the six espeak scripts go to espeak, Latin runs to misaki's English G2P, and everything else, other scripts included, to misaki's Chinese G2P, which keeps any character outside U+4E00-U+9FFF as it is: Lao or Tifinagh letters become "phonemes" that the model's vocabulary then drops, so they are silent | As in the English pipelines (previous row): a script espeak has a voice for goes to it (Bengali → `bn`), and any other is read as "<script> text" (in English, in the Chinese voice) | The same reasons as the previous row: nothing read silently, and one set of rules for every pipeline | 3 of 686 Chinese Wikipedia records (Bengali, Lao, Tifinagh); not compared | `crates/pipeline/tests/parity.rs` (counted apart), `tests/scaling.rs` |
| espeak: language-switch flags | misaki's English fallback keeps espeak's `(ka)…(en-us)` flags when espeak switches language mid-word, so they become phonemes (`(ka)ɡˈamaɹʤˌɔba(An-us)`) | Dropped from every espeak output, as misaki's `EspeakG2P` already drops them. The text's own parentheses are punctuation, kept out of what espeak reads and put back afterwards, so they stay | Brendan's decision (2026-11-03): the flags aren't speech | 1 of 8,700 English records (the Bengali one above); 87 of 1,816 reference requests (fuzz: mostly lone combining marks the fallback spells out, like `hˈɪndi(hi)həlˈʌnt(An)` for a virama), which match the reference once its flags are dropped, except one whose shorter phonemes pack its clauses into different chunks; 0 of the espeak corpus's fallback calls | `crates/espeak` `language_switch_flags_are_dropped_and_parentheses_kept`, `tests/parity.rs`; `crates/pipeline/tests/requests.rs` |
| Pipeline: G2P errors | A G2P error (misaki's `OverflowError` on a number of 400 digits, say, or its Chinese G2P's `ValueError` on a Han character pypinyin has no reading for, in Chinese text) fails the whole request; chunks already streamed stay sent | `chunks` yields `Err` in place of the chunks of the sentence whose G2P failed, then carries on with the next sentence; the caller decides whether to stop | One unreadable sentence shouldn't silence the rest of an article, and the caller still sees every error | 0 of 8,700 English records and 0 of 686 Chinese Wikipedia records (none fail in the reference); 45 of 1,506 generated Chinese records (`zh_mixed_cases.py`, which puts `兙` in on purpose), whose chunks match the reference's up to the failure | `crates/text` `a_g2p_error_stands_in_for_its_sentence`; `crates/pipeline` `a_number_too_large_to_read_fails_only_its_sentence`, `tests/requests.rs` |
| espeak-ng: state between calls | C keeps its globals from one `espeak_TextToPhonemes` call to the next, and phonemizer keeps one library per language, so one request can change later requests for that language: an embedded `\x01B` turns on spoken punctuation and `\x01…Y` say-as mode for good, and a character read ahead at the end of one call is read at the start of the next | Every `text_to_phonemes` call starts from the state a new library has right after `espeak_SetVoiceByName`; the only thing shared between calls is the immutable loaded data. Restoring that state (copying the small part, clearing the large buffers) costs 1–2 µs per call | Untrusted text in one request must not change another user's output | 0 of 140,344 corpus calls; 45% of the adversarial calls on the 12 Kokoro voices and 17% on all 141 (generated texts are full of embedded commands) | C answers from a child forked after `espeak_SetVoiceByName` for every call (`oracle.py pairs`; `--history` gives the reference's behaviour); `earlier_text_does_not_change_later_calls` |
| espeak-ng: digit grouping | `CheckThousandsGroup` (numbers.c:1457) and `TranslateNumber_1` (numbers.c:1611–1621) read past the end of the clause into `TranslateClauseWithTerminator`'s uninitialised stack arrays, so how a long digit string is grouped depends on digits an earlier clause, or an earlier request, left there. fr `LCCN 91052684` after an ISBN reads "…milliard…millions…" | `sbuf`, `words`, `charix`, `number_buf` and `num_wtab` start each clause zeroed, so the output depends only on the text (`LCCN 91052684` → "quatre-vingt-onze millions cinquante-deux mille six cent quatre-vingt-quatre") | Deterministic output; one request can't change how another reads a number | Against the reference: 1 of 140,344 corpus espeak calls (2 fr-fr wrapper outputs, listed in `crates/espeak/tests/divergences.jsonl`) and 15 of 133,931 generated calls. Against C from fresh state: 0 corpus calls (in a new process those bytes happen to be zero, as here) and 6 generated calls, where an earlier clause of the same text left digits there | memcheck on C (`oracle.py --ub`); `earlier_text_does_not_change_number_reading` |
| espeak-ng: `$text` replacements | `TranslateWord`'s skip loop (translate.c:191) runs past the end of a replacement with fewer words than the entry skips, reading stack memory; output varies between runs (es `A.$U.A`) | Stops at the end of the text | Undefined behaviour in C | 0 | ASan |
| espeak-ng: other out-of-bounds reads | On some input C reads outside stack buffers, and sometimes segfaults. Examples: `InterpretCondition` (synthdata.c:618) and `CountVowelPosition`/`isAfterStress` walk off the start of phoneme lists; `MatchRule`'s syllable count (dictionary.c:1766) scans past the end of the clause buffer looking for a space, in 19% of es corpus calls | Reads outside a buffer give 0 and the scan stops at the buffer's end; no crash | Undefined behaviour in C | 0 (the port still gives C's answer on all other 1,359 corpus calls and all other 6,085 generated calls where C reads undefined memory) | ASan, memcheck, fuzzing |

For the espeak-ng rows, records are `espeak_TextToPhonemes` calls: the corpus dump's calls (misaki/phonemizer on the Gutenberg and Wikipedia corpus, 12 voices) and the generated texts (`gen_adversarial.py` and `gen_dict.py`, all 141 voices), compared with C answering each call in order in one process per voice, as the reference does (`oracle.py pairs --history`). The oracle flags calls where C reads out of bounds or reads uninitialised memory (`oracle.py pairs --ub`): 1,360 corpus calls and 6,100 generated calls in the reference's call order, and 1,360 and 4,638 from fresh state. The parity tests run those calls but don't score them, since C's answer depends on whatever memory it read. The parity tests take C's answers from fresh state for every call (`oracle.py pairs`), that is, the reference plus the state-between-calls row.
